# Harden the atelier container (uniform rule of 2026-11-27)

- Date: 2026-11-27
- Type: pull request (card committed by hand — the repository has no
  `make pr` card generator yet)
- Scope: Dockerfile (runtime stage), docker-compose.yml (atelier),
  docker-compose.dev.yml, docs/deployment.md, ADR-0121
- Motive: the atelier container ran as root with every capability.
  The uniform rule of 2026-11-27 hardens every deployed service the
  same way (layered-data, lisage, petrichor).
- Evidence: code read of server/config.ts, stores.ts,
  userLayerStore.ts, editorSessionStore.ts — with DATABASE_URL set,
  no disk write happens in production; smoke boot as uid 1000
  (setpriv, node 22): banner, listen on 8791, /auth/me 401. No
  container build or compose run in this environment (docker
  absent) — stated, not implied.
- Known limits: merging deploys production (deploy.yml runs on every
  push to daily, no rollback); postgres keeps its stock entrypoint
  (chown as root at init, compose network only); the pre-existing
  atelier-data volume stays root-owned (unused while DATABASE_URL is
  set, fail-fast otherwise); the dev override's !reset expects
  compose v2.24+.
